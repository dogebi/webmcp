01 / WHY IT MATTERS

에이전트가 화면을
해독할 필요가 줄어듭니다.

기존 자동화는 화면을 보고, 요소를 찾고, 클릭 결과를 다시 확인합니다. WebMCP는 페이지가 제공하는 작업 설명과 입력 규칙을 에이전트가 먼저 발견할 수 있게 합니다.

02 — WebMCP도구 호출

의도와 입력을 바로 전달

페이지가 기능과 입력값의 모양을 명시합니다. 에이전트는 사용 가능한 도구에서 맞는 작업을 고릅니다.

목표는 모든 브라우저 동작을 없애는 것이 아니라, 명확한 작업을 더 직접적이고 예측 가능한 경로로 연결하는 것입니다.

02 / THE MODEL

페이지가 도구의
작은 안내판이 됩니다.

도구는 현재 열린 페이지의 맥락에서 제공됩니다. 이름은 할 일을, 설명은 사용 목적을, 스키마는 필요한 입력을 알려줍니다. 호출은 페이지가 이미 가진 기능으로 이어집니다.

A

발견

현재 페이지가 어떤 도구를 제공하는지 확인합니다.

B

입력

필드와 스키마를 보고 필요한 값만 전달합니다.

C

실행

사이트 로직이 작동하고 결과가 페이지 맥락으로 돌아옵니다.

03 / TWO API SHAPES

폼에 적거나,
코드로 등록하거나.

두 방식 모두 페이지 기능을 구조화해 공개합니다. 일반 HTML 폼으로 충분하면 선언형으로 시작하고, 폼만으로 표현하기 어려운 조회·상태 흐름은 명령형을 살펴보세요.

TOOL DEFINITION / PICK A ROUTEAPI 02
DECLARATIVE API

기존 폼에 도구 설명을 붙입니다.

폼의 `toolname`, `tooldescription`과 입력 필드 이름을 바탕으로 도구가 표현됩니다. 예시에서는 에이전트가 값을 채운 뒤 사용자가 직접 제출합니다.

<form toolname="search_catalog"
      tooldescription="Search products by keyword"
      action="/search" method="get">
  <label>검색어
    <input name="query" type="search" required>
  </label>
  <button type="submit">검색</button>
</form>

IMPERATIVE API

자바스크립트에서 실행 함수를 연결합니다.

툴 설명과 JSON Schema를 직접 정하고, 기존 로직을 실행 콜백에 연결합니다. 브라우저가 API를 제공하는지 먼저 확인합니다.

const lifetime = new AbortController();

if (document.modelContext?.registerTool) {
  await document.modelContext.registerTool({
    name: "search_catalog",
    description: "Search products by keyword",
    inputSchema: {
      type: "object",
      properties: { query: { type: "string" } },
      required: ["query"]
    },
    annotations: { readOnlyHint: true },
    execute: async ({ query }) => searchCatalog(query)
  }, { signal: lifetime.signal });
}

// 화면 상태가 끝날 때 lifetime.abort()를 호출합니다.

04 / NOT THE SAME LAYER

MCP 서버와 WebMCP,
연결 지점이 다릅니다.

이름은 비슷하지만 같은 구성요소를 뜻하지 않습니다. 기존 MCP 서버를 대체한다고 단정하기보다, 브라우저 안 페이지 작업을 설명하는 별도의 경로로 이해하면 좋습니다.

SERVER TOOLING01

서버가 도구를 호스팅하고 클라이언트가 연결합니다. 브라우저 페이지 밖의 데이터와 시스템을 다루는 데 쓰일 수 있습니다.

OR
PAGE TOOLING02

페이지가 도구 인터페이스를 공개하고, 실행은 해당 페이지의 기존 기능으로 연결합니다. 서버/API가 필요한 서비스라면 내부 로직에서 계속 사용할 수 있습니다.

05 / SHIP WITH CARE

좋은 도구는
경계도 분명합니다.

WebMCP 메타데이터는 인터페이스입니다. 인증, 권한 검사, 입력 검증을 대신하지 않습니다. 중요한 작업은 서버 측에서도 다시 검증하고, 사용자 확인이 필요한 동작은 그대로 확인받아야 합니다.

01

작업 하나, 도구 하나

이름과 설명만 읽고도 언제 호출할지 알 수 있게 범위를 좁힙니다.

02

입력은 명확하게

스키마와 HTML 필드에 필수값, 단위, 선택지를 분명히 담습니다.

03

권한은 실행 때 확인

현재 사용자, 페이지 상태, 리소스 권한을 실행 시점에도 검증합니다.

04

변경 전에는 검토

결제·전송·삭제처럼 되돌리기 어려운 작업은 사람 확인 흐름을 둡니다.
